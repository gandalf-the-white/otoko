#+title: Syslog AI on FreeBSD
* Introduction
Just to brainstorm about a multi-agent system conception thank to AI. The idea is to analyze different logs from a /FreeBSD/ server using /jails/ as architecture.
It consists of five main layers: data collection, normalization, multi-agent analysis, diagnostics, and reporting.

* Isolation
Our architecture is based on three fundamental principles.
The domain model is independent of the AI. The LogBatch, Incident, DiagnosisResult, and AnalysisReport structures are Rust objects. They must not depend directly on Rig’s or Ollama’s internal types.
Agents have only the capabilities they need. The LogAnalyzer interprets logs, the Correlator establishes relationships, the SeverityAgent assesses severity, and the DiagnosisAgent proposes hypotheses that it can enrich with remote observations. The ReporterAgent simply synthesizes the results.
The orchestrator remains in control of the workflow. It is Rust—not the LLM—that determines the order of major steps, validates results, handles errors, and saves the report.

Each agent has a specific specialization, but their interactions are governed by Rust contracts.
This architecture is particularly well-suited to our training: it facilitates testing, understanding of behavior, and control over LLM calls.
Eventually, it may evolve into a more distributed architecture, with agents running in separate processes, possibly on different machines.
The next step I recommend is to consolidate the contracts between modules, then introduce PostgreSQL persistence for incidents, diagnostics, and observations. We can then use this history to perform temporal correlations, detect recurring incidents, and lay the groundwork for building a knowledge graph.
